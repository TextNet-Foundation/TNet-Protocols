# Спецификация протоколов TNet

Этот документ описывает три основных протокола **TNet** — децентрализованной текстовой сети:

- **UTNP** — Universal Text Negotiation Protocol
- **TMUTP** — TMkUp Transfer Protocol
- **TBIP** — TNet Binary Information Protocol

Все протоколы работают поверх TCP и используют текстовый формат запросов и ответов.

---

## Коды состояния TNet

TMUTP и TBIP используют общую сетку кодов состояния — **TNet Status Codes**. Коды одинаковы для обоих протоколов, хотя некоторые из них могут не иметь специального применения в одном из протоколов. Полученный код следует интерпретировать согласно этой таблице.

| Код | Название | Описание |
|-----|----------|----------|
| 20 | OK | Успешный ответ с телом |
| 21 | MOVED | Ресурс перемещён |
| 22 | OK EMPTY | Успешный ответ с пустым телом |
| 23 | MULTIPLE CHOICES | Доступно несколько вариантов |
| 30 | BAD REQUEST | Некорректный запрос |
| 31 | NOT FOUND | Документ или ресурс не найден |
| 32 | FORBIDDEN | Доступ запрещён |
| 40 | SERVER ERROR | Внутренняя ошибка сервера |
| 41 | NOT IMPLEMENTED | Метод или функциональность не реализованы |
| 42 | SERVICE UNAVAILABLE | Служба временно недоступна |
| 50 | METHOD NOT ALLOWED | Метод не разрешён |
| 51 | VERSION NOT SUPPORTED | Версия протокола не поддерживается |

## 1. UTNP — Universal Text Negotiation Protocol

**Версия:** 1.0  
**Порт:** 34  
**Транспорт:** TCP  
**Назначение:** обнаружение служб и согласование протоколов. UTNP не передаёт содержимое и не может использоваться в URL.

### Запросы

```text
UTNP/1.0 NEGOTIATE <protocol1>,<protocol2>,...
UTNP/1.0 LIST
```

**Примеры:**

```text
UTNP/1.0 NEGOTIATE tmutp
UTNP/1.0 NEGOTIATE tmutp,tbip
UTNP/1.0 LIST
```

### Ответы

**Успешное согласование:**

```text
UTNP/1.0 START PROTOCOL <name> <version> <host> <port>
```

**Список доступных протоколов:**

```text
UTNP/1.0 AVAILABLE
<name1> <version1> <host1> <port1>
<name2> <version2> <host2> <port2>
...
```

**Ошибка:**

```text
UTNP/1.0 ERROR <message>
```

**Ошибка со списком доступных протоколов (если запрошенный протокол не поддерживается):**

```text
UTNP/1.0 ERROR Unsupported protocol
UTNP/1.0 AVAILABLE
<protocol1> <version1> <host1> <port1>
...
```

**Ошибка версии UTNP:**

```text
UTNP ERROR - UNSUPPORTED UTNP VERSION, SUPPORTED UTNP/1.0
```

### Поведение сервера

1. Ожидать подключения на порту `34`.
2. Принять строку запроса.
3. Если версия UTNP не равна `1.0`, вернуть ошибку версии и закрыть соединение.
4. Если запрос — `LIST`, вернуть список всех доступных протоколов.
5. Если запрос — `NEGOTIATE`:
   - Проверить, поддерживается ли хотя бы один из перечисленных протоколов.
   - Если да, вернуть `START PROTOCOL` с параметрами первого поддерживаемого протокола.
   - Если нет, вернуть `ERROR Unsupported protocol` и список `AVAILABLE`.
6. Закрыть соединение после отправки ответа.

### Стандартные протоколы TNet

| Название | Версия | Порт по умолчанию |
|----------|--------|-------------------|
| `tmutp` | 1.0 | 100 |
| `tbip` | 1.0 | 81 |

## 2. TMUTP — TMkUp Transfer Protocol

**Версия:** 1.0  
**Порт:** 100  
**Транспорт:** TCP  
**Назначение:** передача документов TMkUp (только текст).

### Формат запроса

**GET:**

```text
TMUTP/1.0 GET <path>
```

**POST:**

```text
TMUTP/1.0 POST <path>
Content-Length: <length>
<body>
```

**Примеры:**

```text
TMUTP/1.0 GET /index.tmkup
TMUTP/1.0 GET /docs/
TMUTP/1.0 GET /about
TMUTP/1.0 POST /feedback
Content-Length: 25

name=John&message=Hello
```

### Коды состояния

TMUTP использует сетку **TNet Status Codes** (см. выше).

### Формат ответа

```text
TMUTP/1.0 <code> <name>
Content-Type: text/tmkup
Content-Length: <length>
[Last-Modified: <date>]
[Location: <new-path>]

<TMkUp body>
```

**Примеры:**

```text
TMUTP/1.0 20 OK
Content-Type: text/tmkup
Content-Length: 100
Last-Modified: 2024-06-10

---tmk-meta
title: "Home"
---tmk-meta
# Welcome!
```

```text
TMUTP/1.0 21 MOVED
Location: /index.tmkup
Content-Type: text/tmkup
Content-Length: 0
```

```text
TMUTP/1.0 31 NOT FOUND
Content-Type: text/tmkup
Content-Length: 80

---tmk-meta
title: "31 — Not Found"
---tmk-meta
# 31 — Document not found
```

```text
TMUTP/1.0 51 VERSION NOT SUPPORTED
Content-Type: text/tmkup
Content-Length: 90

---tmk-meta
title: "51 — Unsupported Version"
---tmk-meta
# Server supports only TMUTP/1.0
```

### Заголовки

**Запрос:**

| Заголовок | Описание | Пример |
|-----------|----------|--------|
| `Content-Length` | Длина тела запроса (для POST) | `Content-Length: 25` |

**Ответ:**

| Заголовок | Описание | Пример |
|-----------|----------|--------|
| `Content-Type` | Всегда `text/tmkup` | `Content-Type: text/tmkup` |
| `Content-Length` | Длина тела | `Content-Length: 1024` |
| `Last-Modified` | Дата последнего изменения | `Last-Modified: 2024-06-10` |
| `Location` | Новый путь (для `21 MOVED`) | `Location: /index.tmkup` |

### Поведение сервера

1. Принять запрос.
2. Проверить версию. Если она не равна `1.0`, вернуть `51 VERSION NOT SUPPORTED`.
3. Если метод — `GET`:
   - Если путь заканчивается на `/`, искать в каталоге файл `index.tmkup`.
   - В противном случае искать файл **строго по указанному имени** (не добавлять расширение).
   - Если файл найден, вернуть `20 OK` с его содержимым.
   - Если файл не найден, вернуть `31 NOT FOUND`.
   - Если путь содержит параметры (например, `/search?q=...`), сервер обрабатывает их по своему усмотрению.
4. Если метод — `POST`:
   - Прочитать тело запроса (формат `application/x-www-form-urlencoded`).
   - Обработать данные.
   - Вернуть `20 OK` с подтверждением или `22 OK EMPTY`.
5. Если метод не `GET` и не `POST`, вернуть `50 METHOD NOT ALLOWED`.
6. Если формат тела не поддерживается, вернуть `41 NOT IMPLEMENTED`.

## 3. TBIP — TNet Binary Information Protocol

**Версия:** 1.0  
**Порт:** 81  
**Транспорт:** TCP  
**Назначение:** передача бинарной информации (изображений, аудио, видео).  
**Исключение:** исполняемые файлы (`.exe`, `.bin`) не считаются бинарной информацией.

### Формат запроса

**GET:**

```text
TBIP/1.0 GET <path>
```

**HEAD (необязательно):**

```text
TBIP/1.0 HEAD <path>
```

**Примеры:**

```text
TBIP/1.0 GET /logo.png
TBIP/1.0 GET /audio/song.mp3
TBIP/1.0 HEAD /video/clip.mp4
```

### Коды состояния

TBIP использует сетку **TNet Status Codes** (см. выше). Код `41 NOT IMPLEMENTED` входит в общую сетку, хотя может не использоваться каждым сервером TBIP.

### Формат ответа

```text
TBIP/1.0 <code> <name>
Content-Type: <type>
Content-Length: <length>
[Last-Modified: <date>]
[Location: <new-path>]

<binary data>
```

**Примеры:**

```text
TBIP/1.0 20 OK
Content-Type: image/png
Content-Length: 12345
Last-Modified: 2024-06-12

<binary PNG data>
```

```text
TBIP/1.0 31 NOT FOUND
Content-Type: text/plain
Content-Length: 20

File not found
```

### Типы содержимого

| Тип | Описание |
|-----|----------|
| `image/png` | PNG |
| `image/jpeg` | JPEG |
| `image/gif` | GIF |
| `image/webp` | WebP |
| `audio/mpeg` | MP3 |
| `audio/ogg` | OGG |
| `video/mp4` | MP4 |
| `video/webm` | WebM |
| `application/octet-stream` | Любой другой бинарный файл (клиент может предложить сохранить его) |

### Поведение сервера

1. Принять запрос.
2. Проверить версию. Если она не равна `1.0`, вернуть `51 VERSION NOT SUPPORTED`.
3. Если метод — `GET` или `HEAD`:
   - Искать файл **строго по указанному имени** (не добавлять расширение).
   - Если файл найден, определить MIME-тип по расширению (или по сигнатуре файла).
   - Вернуть `20 OK` с заголовками и телом (для `HEAD` — только заголовки).
   - Если файл не найден, вернуть `31 NOT FOUND`.
   - Если путь указывает на каталог, вернуть `31 NOT FOUND` (по умолчанию индексный файл не используется).
4. Если метод не `GET` и не `HEAD`, вернуть `50 METHOD NOT ALLOWED`.

**Content-Length:** сервер всегда указывает полный размер бинарных данных в байтах. Chunked transfer не используется. Клиент считывает ровно `Content-Length` байтов.

## Работа TNet

```text
Клиент подключается к порту 34 (UTNP)
  |
  |-- UTNP/1.0 NEGOTIATE tmutp
  |<-- UTNP/1.0 START PROTOCOL tmutp 1.0 example.com 100
  |
  |-- закрывает соединение
  |
  |-- подключается к example.com:100 (TMUTP)
  |-- TMUTP/1.0 GET /index.tmkup
  |<-- TMUTP/1.0 20 OK + TMkUp
  |
  |-- (если требуется изображение)
  |-- снова подключается к UTNP на порту 34
  |-- UTNP/1.0 NEGOTIATE tbip
  |<-- UTNP/1.0 START PROTOCOL tbip 1.0 example.com 81
  |
  |-- подключается к example.com:81 (TBIP)
  |-- TBIP/1.0 GET /logo.png
  |<-- TBIP/1.0 20 OK + бинарные данные PNG
```
